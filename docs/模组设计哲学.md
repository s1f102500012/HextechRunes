# 模组设计哲学

> 适用范围：本仓库的 HextechRunes 本体与 HextechRunesSponsorPack 拓展包。
> 读者：参与本仓库创作、重构与修复的维护者和贡献者。
> 来源：2026-09 海克斯大乱斗补丁体系重构的取证与裁决，
> 以及 KeystoneRunes / EndlessMode / IntegratedStrategyEvents 等模组积累的教训；2026-09 下旬海克斯的四轮兼容性审计、手柄与战斗特效修复补充了第 1–9 节的若干条。
> 这里只写会反复用到的原则，不写单个案例的细节。

## 0. 一句话

**模组是游戏的客人，不是游戏的主人。** 每一处对原版的改动都要能回答三个问题：为什么原版给的扩展点不够用、
别的模组会不会因此失效、两个联机客户端会不会因此算出不同结果。答不上来的改动不要写。

## 1. 扩展点优先级（从上到下，能用上面的就不用下面的）

1. **内容本身**：自己的 `RelicModel` / `ModifierModel` / `CardModel` / `PowerModel` / `EventModel`。它们天然收到原版全部 `Hook.*` 回调，
   `ShouldPlay`、`TryModifyKeywordsInCombat`、`ModifyDamage*`、`AfterRewardTaken`、`AfterCardEnteredCombat` 等虚方法覆写零冲突。
2. **官方事件与公开 API**：`ModManager.OnMetricsUpload`、`RunManager.RoomEntered/RoomExited`、`ModHelper.AddModelToPool`、
   `ModelDb.get_AllCardPools` 后缀并池、`SetLocalization`、`LocManager` 的模组 loc 表合并、`PackedIconPath` 之类的虚路径属性。
3. **Harmony postfix**：只读或在原结果上加减，永远不阻止原方法。
4. **Harmony 非跳过前缀**：观察、记账、改参数，`return true`。
5. **Harmony 跳过型前缀（`return false`）**：最后手段。必须同时满足：原版方法没有等价 Hook；替换是有条件的（只对本模组激活时）；
   在文档里写明理由；进"原版拷贝守卫"冻结原方法 IL，游戏更新时自动告警。
   替换体要对照原方法**完整的异步状态机**逐步复制（动画、能量、抽牌这类前置步骤都算），只改真正要改的那一步；
   只 grep 到一行调用就动手，必然漏掉其余步骤。
   只想去掉原方法里的一个副作用（比如一次音效）时，用 `AsyncLocal` 作用域标记加一个只在作用域内生效的窄前缀拦那一个调用，不复制整段逻辑。
6. **Transpiler**：本仓库默认不用。

判断"官方 Hook 够不够用"的方法只有一个：反编译原方法，看它内部调不调 `Hook.*`。`CardModel.CanPlay` 内部就调 `Hook.ShouldPlay`，
`RelicModel.Icon` 直接读虚属性，`CreatureCmd.GainBlock` 内部调 `Hook.ModifyBlock`——这些地方打前缀就是没做功课。
反过来，`CreatureCmd.Heal` 对 amount=0 也播音效、`CardPileCmd.Draw` 的返回值没有 Hook 能替换，这些保留跳过前缀是有据可查的。

## 2. 绝对不碰的中枢

以下位置的补丁会波及所有模组，一律禁止，历史上每一个都引发过冲突投诉：

- `Log.*`：拦日志只为压自己的假警告，去修根因。
- `Hook.*` 静态分发方法的前缀（尤其 `Priority.First`）：这是所有模型回调的总线；要"批处理"就自己组织流程，不要吞别人的事件。
- 联机通道：`NetHost/NetClientGameService.OnPacketReceived`、`ModManager.GetGameplayRelevantModNameList`、SavedProperty net-id 表重排。
  联机校验的输入只能由游戏决定；要表达兼容性用 manifest 版本号，要诊断入房失败就只做诊断输出。
- `ReflectionHelper.ModTypes` 之类的类型贡献入口：只允许作为官方 `AssociateAssemblyWithMod` 都失败后的最后回退，且不能与官方路径同时生效。
- 其他模组的类型：不要扫描已加载程序集给第三方的子类打补丁（充能球、Power、卡牌都一样）。第三方内容保持原版行为，是它们的权利。
- 全局兜底吞异常：Finalizer 或 catch 只能限定到本模组能证明是自己造成的对象和路径。覆盖整个原版入口，会把第三方的失败伪装成成功。

## 3. 冲突面纪律

- **每个补丁自描述**：`[HarmonyPatch]` + 本模组的元数据属性（ID、所属功能、影响的内容、是否可选），由一个统一应用器逐条应用、逐条报告成败。
  入口只做编排，不允许"安装顺序即契约"。
- **执行序只由优先级表达**：`[HarmonyPriority]` / `[HarmonyBefore]` / `[HarmonyAfter("<其他模组 Harmony id>")]`。跳过型前缀默认 `Priority.Low`，
  让别人的前缀先跑；聚合型修饰（最终封顶、最终倍率）用 `Priority.Last` 并 `HarmonyAfter` 已知的同类框架。
- **启动时自报冲突**：列出与其他 owner 共享的补丁目标，对"第三方前缀排在本模组跳过型前缀之后"的情况单独 Warn 点名。
  玩家报冲突时这行日志就是答案。
- **可选目标降级为 Info**：目标方法在某个游戏版本不存在时，单个补丁失败，不连累同组；声明了元数据却没有目标的补丁必须报错，不能静默消失。
- **私有成员访问集中管理**：找不到就在启动摘要里列出并降级功能，不要各文件自持 `FieldInfo` 然后悄悄失效。
  每一处私有访问都要在注释里写它对应的原版字段名和版本。
- **UI 用公开 API**：主菜单按钮用 `SetLocalization` + 自己的 loc 表合并，焦点逻辑靠原版 `_Ready` 之前插入节点让原版自己接管；
  不读 `_locString`、`_lastHitButton` 这类字段。
- **手柄跟随游戏自己的输入层**：是否处于手柄模式读 `NControllerManager`，不从事件类型猜（Steam Input 下没有原始手柄事件）；
  确认键是原版的 `ui_select`，Godot 按钮认的 `ui_accept` 没有任何手柄键映射。自定义界面要么接入原版 `IScreenContext` 或覆盖层栈，
  要么自己屏蔽背后界面的焦点并处理返回键。鼠标模式下不主动抢焦点。
- **规范模型上不读实例状态**：图鉴和第三方会遍历规范模型，读 `Title`、`Type`、`HoverTips`、计数器之类的 getter；
  原版 `Owner` 在规范模型上直接抛异常。自有 getter 和对原版 getter 的 postfix，都要先判 `IsCanonical` 再碰 `Owner`、`CombatState`。
- **兼容桥不丢参数**：为多版本签名写的基类转发，如果把原版参数（如回合钩子的 `participants`）吞掉，子类就再也实现不了原版的守卫；
  需要的参数通过新的虚方法原样传下去，默认行为不变。
- **不借用无关字段做身份标记**：序列化数据里要认出自家的东西，用明确的来源 ID；借一个语义无关的布尔位，会把第三方同样借用它的数据认成自己的。
  换标记时保留旧格式的读取。

## 4. 联机确定性

- **所有共享状态改动必须在两端一致执行的逻辑路径里发生**：命令队列内、`Hook.*` 回调内、`RunStarted` 之类的对称事件内。
  `LocalContext.IsMe` / `IsLocalPlayer` 分支只允许处理 UI、输入和上报选择。
- **查询钩子不写共享状态**：`Modify*` / `TryModify*` / `Should*` 会在真实执行之外被调用（原版 UI 每帧算费用和伤害，随机数预测等模组拿真实生物和牌模拟出牌、施加能力、受伤），只在本机发生。
  计数从两端同步的战斗记录里重算，或者在真实路径独有的 `Before*` / `After*` 回调里记账；查询钩子顶多读这些记账。`AsyncLocal` 命令作用域不足以区分真实与模拟：原版延迟通知会把它带进模拟。
- **不消耗共享 RNG 做本地 UI 随机**；候选池会变时同步最终模型 ID 而不是 index。
- **不引入墙钟依赖**（实时回血、按秒触发）；做不到对称就在联机里禁用该内容，而不是硬同步。
- **持久状态用 `[SavedProperty]`**，并接受它的代价：属性集合决定 net-id 布局，新增/改名/删除任何一项都与旧版本不兼容，
  必须随版本号发布并在更新日志里写明"无法与上一版联机"。属性名集合要有快照测试守着。
- **原版序列化的位宽是硬上限**：例如 `SerializablePotion.SlotIndex` 只有 4 bit（最多 16 个药水槽）。给原版计数类状态加成前先看它的 `Serialize`。
- **先算再杀**：`CreatureCmd.Kill` 完成后怪物已移出战斗、`CombatState` 置空，任何"杀完再判定"的逻辑都会失败。
- **同一回合开始序列内的先后**：`RoundNumber` 在切到玩家侧时先递增，回合开始各 hook 看到同一回合号；"回合开始施加、回合开始到期"的临时状态必须按回合号防重。
- **回合钩子看 participants**：额外回合只带单个玩家重入回合开始/结束钩子，绑定持有者的效果要确认持有者在本次 participants 里，否则会跟着队友的额外回合触发。
- **await 之后重新核对**：等待前检查过的前提（目标存活、仍在战斗、仍是同一个战斗容器、行动没被改写）在等待后都可能失效，写入共享状态前再核一次。
- **异步作用域在同步路径上退出**：用 `AsyncLocal` 标记命令作用域时，async 方法里的赋值不会回写调用方。出栈要放在补丁的同步 Postfix 与 Finalizer 里，
  异步续体只做清账；否则调用方之后的结算会一直看到残留的作用域。
- **表现层不能先于同步写入抛异常**：视觉、音效、节点查找全部包 try/catch 并放在状态写入之后。
  闸门、标志位这类控制状态的释放，不能排在可能抛错的 UI 调用后面。
- **表现层在主线程读写节点**：战斗命令不一定跑在主线程，Godot 在其他线程读全局坐标会得到原点；读坐标、挂节点都推到主线程执行。
  特效挂载沿用本模组已经实机验证过的父节点和坐标系，不混用另一套容器。

## 5. 版本兼容

- 只发布真正维护的游戏版本，csproj 拦住其它目标值；死代码分支一律删。
- 版本差异写成**整文件 `#if` 的分部文件**（`Foo.Legacy.cs` / `Foo.Official.cs`），共享代码里不写 `#if`。
  唯一允许的行内 `#if` 是原版虚方法或 `Hook.*` 签名随版本变化的覆写与补丁目标声明。
- 同一份源码按版本切引用目录多编译，用加载器按宿主版本选变体；不要指望单 DLL 跨越虚方法签名变化。
- 游戏更新后的检查清单：原版拷贝守卫是否报 DRIFT、补丁清单是否有解析不到的目标、私有成员缺失列表是否为空、SavedProperty 快照是否被迫变动。
- **加载器找不到兼容变体就停**：宿主版本已知、却没有不高于它的有效变体时，显式报错并停止加载，不回退到更新的变体。
- **状态标志只记录已经发生的事实**："已尝试/已冻结"和"已成功"分成两个标志；失败路径记错误级日志，不宣称完成。
- **配置向前兼容**：读到比当前版本新的配置，只在内存里使用，不回写覆盖；类型化配置会丢掉它不认识的字段。

## 6. 内容设计的边界

- **想改一张原版卡的行为，先问能不能发一张自己的卡。** 替换 16 张原版卡的 `OnPlay`、重写 8 个原版 Power 的回调，
  在技术上可以做到条件化、可以做到有守卫，但它天然排他，别的模组永远会先怀疑你。这不是重构能解决的，是设计选择。
- **想给玩家一个"机制"，先问能不能把它写成一个"效果"。** "同一张牌可以多重附魔"是机制：它要求偷换 `card.Enchantment` 槽位、复制原版 `CanEnchant` / `CardCmd.Enchant` / 卡面刷新逻辑，并让全游戏所有 `card.Enchantment is X` 的读取失明；而社区已经有 MultiEnchantmentMod 在做这件事，还带 IL 重写器替所有模组兜底。"战斗结束时给随机牌加一个随机合法附魔"是效果：它只是 `CardCmd.Enchant` 的一个调用方，"合法"的定义权交给 `enchantment.CanEnchant(card)`，装不装多附魔模组都自洽。海克斯拓展包 0.9.2 用后者替换了前者，删掉 1,500 行与 12 个补丁。
- **想改一个原版 Power 的行为，先问能不能在施加点换成自己的同名 Power。** 这比去补原版 Power 的类型、回合回调、人工制品判定窄得多，
  其他玩家的原版 Power 照旧，也不会在规范模型上出事。
- 加到原版池里的内容要过 `CardFactory.FilterForCombat` 之类的官方过滤，不要把 Ancient / Basic / Event 类内容漏进生成池。
- 全局改怪物数值、全局改奖励结构的功能，只在本模组的 Modifier 激活时才挂钩，不能常驻。为本模组的问题修补原版全局流程（例如存档前补历史）也一样要门控。
- **删除内容走完整清单**：注册表、配置迁移列表、引用它的助手、各语言文案、图标、内容 TXT 一起清；先确认旧存档里的这份内容有原版回退路径。
- 数值调整、文案、触发时机不在结构重构里顺手改；改了要在更新日志里单独列出。

## 7. 玩家的信任

- **遥测默认关闭或首次启动明示**，游戏内必须有开关，传输走 HTTPS。默认开启且无开关是评论区最容易发酵的一条。
- **不做完整性指纹校验**：自行编译、二创、修改版都是合法用法，"官方构建校验"只会制造警告和敌意。联机分叉诊断只能是诊断。
- 更新检查可以有，但要能关。
- 未签名 DLL 被 Windows Smart App Control 拦截没有代码解，只能如实告知。

## 8. 护栏与验证（按改动风险选择）

使用项目现有检查验证本次改动，不为形式重复建测试。已足以覆盖实际风险后停止追加验证；相关检查失败则继续定位并修复本次引入的问题。

| 改动 | 检查范围 |
| --- | --- |
| 文档、拼写 | 差异、引用和链接；不启动游戏 |
| 本地化、换行 | JSON、标签、同键变量及受影响文本；交付要求包含包时重新打包 |
| 贴图、场景资源 | 尺寸/alpha、引用、Godot导入产物及受影响资源显示 |
| 战斗公式、触发 | 当前目标编译、能区分旧错误与新行为的最小回归、相关动态显示值 |
| 模型ID、SavedProperty、补丁结构 | 相关身份/保存字段/补丁清单快照，目标解析和受影响序列化路径 |
| 发布、多版本适配 | 所有实际声明支持的目标分别构建，发行包与部署一致；有完整运行时的版本才做加载验证 |

- 编译目标由当前项目维护范围决定，不固定为三个。发布构建零错误，警告应解决或说明依据，不隐藏诊断。
- 涉及补丁、可变静态字段或SavedProperty集合时检查对应快照；补丁元数据要求ID唯一，目标可解析或具备明确的动态应用路径。不要为了纯文本改动新增整套补丁框架。
- 测试进程中不执行可能触碰Godot原生层的 `[HarmonyPrepare]` / `[HarmonyTargetMethod]`；目标解析检查需要安全的元数据路径。
  测试进程里调用原版 `Log` 也会崩溃：要测的纯逻辑不写日志，日志留给调用方。
- **外部审计逐条对照原版核实**：结论按实际支持的每个游戏版本的程序集反编译核对，分清"分支确定"和"实机复现"。
  旧的离线反编译可能已经过期，关键契约以对应版本的程序集为准。审计方取不到源码时直接提供源码包，不接受基于补丁索引的推测。
- **视觉效果以实机截图为准**：看不到画面就不要连续堆参数；同一方向被否两次，回到上一个被接受的版本。
- 补丁体系重构需要前后目标、种类、优先级、同目标执行顺序及必要IL守卫的等价性证据；文件搬移检查对应目标集合，而非每轮重复全仓库测试。
- 初始化、依赖、补丁或资源加载链变化时，必要的headless检查要看到目标模组和诊断实际执行。进程退出0、模组被禁用或只运行打包脚本均不代表加载验证通过。
- headless不天然隔离用户配置。只管理本次创建的进程和临时文件，保留原有设置；不为通过检查擅自启用模组或修改玩家存档。
- 用户保留实机测试权时，交付可复查的源码、必要构建/包和测试要点。分别说明编译、资源检查、加载、实机、存档及联机验证到哪一层，不把未执行的检查写成通过。

## 9. 交付与文档

- 每个保留的非常规补丁都要有一张裁决表：目标、为什么官方 Hook 不够、替代方案评估过什么、结论。审阅者看表，不看代码。
- 更新日志按玩家视角分【优化】【修复】【注意】，句末分号，不写内部术语；兼容性断裂（联机不兼容、存档字段变化）必须单独列出。
- 本仓库直接维护源码、可编辑资源、开发文档、工具及工坊发布配置；已完成的旧评审和重构计划从当前文件树移除，仍生效的结论纳入开发规范。游戏程序集、构建产物、凭据、原始对局数据和运行日志不进入 Git。
- **直接在本仓库协作**：外部 PR 与维护者修改都进入同一条开发历史。开始修改前同步远端并检查工作区差异；不再向私有开发库回灌，也不再用单向镜像覆盖公开贡献。
  基于旧版本的本地化 PR 按键三方合并，已改过机制的条目以新效果为准，专有名词以游戏包内的官方译名为准。
- 维护者的新提交使用 Natsuki，不附加 AI 署名；外部贡献、共同作者及历史提交保留各自署名，不统一改写作者。

## 10. 设计自检（相关改动时使用）

涉及补丁、共享状态或版本边界时，核对第1–5节：扩展点是否足够、是否触碰共享中枢、跳过前缀是否有依据、两端状态与RNG是否一致、身份/保存字段是否改变，以及版本差异是否隔离。
新增 getter、异步流程或回合钩子时，再看三点：规范模型上会不会读到实例状态、await 之后前提是否还成立、持有者是否在本次 participants 里。

只对本次相关项取证，不把自检清单复制进每次回复。风险或交付范围改变时更新检查选择。
